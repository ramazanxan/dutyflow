# DutyFlow

Веб-приложение для распределения обязанностей между людьми — семья, квартира, команда, учебная группа.

Участники входят без регистрации (Supabase Anonymous Auth), присоединяются к группе по коду приглашения и видят общие задачи в реальном времени.

## Стек

- React 19 + TypeScript + Vite
- Tailwind CSS v4
- Supabase (Postgres, Anonymous Auth, Realtime, RLS)
- React Router (HashRouter — требование GitHub Pages)
- TanStack Query
- Lucide Icons

## Разработка

```bash
npm install
cp .env.example .env   # заполнить значениями своего Supabase-проекта
npm run dev
```

Дев-сервер: http://localhost:5173/dutyflow/

## Сборка

```bash
npm run build
```

## База данных

Миграции лежат в `supabase/migrations/` и применяются по порядку.

Проще всего — через SQL Editor в панели Supabase: открыть каждый файл по очереди
(`..._schema.sql` → `..._functions.sql` → `..._rls.sql`) и выполнить.

Либо через CLI:

```bash
npx supabase link --project-ref <ref>
npx supabase db push
```

## Деплой

Push в `main` запускает GitHub Actions → GitHub Pages.

В настройках репозитория нужно задать секреты:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

Во фронтенде используется только публичный anon key — доступ к данным ограничивается через RLS.

## Этапы

1. ✅ Setup — каркас, Tailwind, роутинг, CI/CD
2. ✅ Supabase — схема БД, RLS, Realtime
3. ✅ User — anonymous auth и профиль
4. ✅ Workspace — группы, приглашения, роли
5. ✅ Tasks — CRUD обязанностей
6. ✅ Realtime — живые обновления
7. ✅ XP — баллы, штрафы, статистика
8. ✅ Notifications — уведомления и напоминания
9. ✅ Calendar — календарь и повторяющиеся задачи
10. ✅ Polish — тёмная тема, нижняя навигация, офлайн
11. ✅ Deploy — прод на GitHub Pages

Отложено за пределы первой версии: kanban, шаблоны задач, автораспределение,
передача задачи другому участнику, достижения, push-уведомления.

## Решения, которые стоит знать

Бэкенда нет — только статический фронтенд и Supabase. Отсюда три вещи:

- **Просрочка не хранится в базе**, а вычисляется из срока. Иначе понадобился бы
  фоновый процесс, переписывающий статусы.
- **Штрафы и напоминания начисляются при заходе в группу**, а не по расписанию.
  Повторно не срабатывают — мешают уникальные индексы на событие.
- **Следующую повторяющуюся задачу создаёт триггер в базе**, поэтому это работает
  независимо от того, кто и с какого устройства нажал «Выполнить».

RLS построен на `security definer` функциях `is_workspace_member` и
`is_workspace_admin`: прямые политики на `workspace_members` уходили бы в
рекурсию. Вступление в группу идёт через `join_workspace`, чтобы не открывать
чтение таблицы групп по коду всем подряд.
